# Third-party control planes for supervising many Claude Code agents — landscape as of 2026-09-06

## 0. Method, scoring key, and what changed this summer

**Method.** Every number below was fetched today (GitHub API via `gh`, repo READMEs/docs, official Claude Code docs, launch posts, Hacker News Algolia API). Where a source could not be fetched, that is stated. Stars are as of 2026-09-06.

**Scoring (0 absent / 1 partial / 2 solid):**
- **A** Morning intake: define the day's work as a goal/mission or a set of tickets.
- **B** Breakdown: produce plans, or require each agent to write a plan that is accepted before implementation.
- **C** Continuously track many Claude Code agents until done, with an acceptance/verification step per task.
- **D** Interruption discipline: batch ALL agents' questions into one digest at most hourly, with decision-ready context; escalate immediately only when truly urgent.
- **E** Orchestrates Claude Code specifically (local CLI in worktrees, desktop app, or cloud).
- **F** One place to look; minimal context switching.

**Things released or changed June–September 2026 that reshape this list (all verified):**
- **Anthropic shipped most of the "manage many sessions" surface first-party.** Agent View (`claude agents`, `claude --bg`, May 11) groups background sessions into *Pinned / Ready for review / Needs input / Working / Completed*, lets you peek-and-reply without attaching, emits `Notification` hooks of type `agent_needs_input` / `agent_completed`, exposes `claude agents --json`, and moves each dispatched session into its own worktree. Cross-session messaging (`ListAgents`/`SendMessage`, v2.1.224, late July) reaches local, other-machine and cloud sessions, with `notify_when_idle` one-shot notices (v2.1.236) and a per-session Unix inbox socket (`CLAUDE_CODE_MESSAGING_SOCKET`) that scripts can post into. `/goal` (evaluator-judged completion, 30 min → 1 h → 2 h check-in backoff, capped at 3 idle check-ins since 2.1.246). Dynamic workflows (`ultracode`, up to 1,000 agents/run, approval card before the run, adversarial cross-verification). Routines (cloud cron/API/GitHub triggers, hourly minimum, no permission prompts during runs). Channels (Telegram/Discord/iMessage pushed *into* a running session, with permission relay). `PreToolUse` hooks can now return `permissionDecision: "defer"` on `claude -p` sessions: the process exits with `stop_reason: "tool_deferred"`, the pending call is preserved on disk with **no timeout**, and you resume with `--resume` when the human has answered. `--permission-prompts none` (2.1.259, Sep 3) for unattended hosts. Agent teams remain experimental (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`) and, notably, "Claude Code approves the plan in the lead's session as soon as the request arrives, without the lead reviewing it."
- **Terragon shut down** (Feb 9, 2026; code open-sourced as a snapshot). **Vibe Kanban's** last push is 2026-04-24 (Bloop shut down in April; "community-maintained"). **Crystal** was deprecated Feb 2026 in favour of **Nimbalyst** (1,664 stars, pushed 2026-09-05). **HumanLayer's** repo last pushed 2026-06-19 and is described by the community list as "code now largely deprecated". **Claude Flow was renamed Ruflo** (`ruvnet/ruflo`, 70,961 stars). **Gas Town and Beads moved** to the `gastownhall` org (17,946 and 26,952 stars).
- **New entrants created since June 2026 that matter for this brief:** Operator (`iishyfishyy/operator-oss`, created Jul 13, 201 stars, "single inbox displaying sessions awaiting user input"), Open Session (`tellahq/opensession`, created Jun 8, 356 stars, Slack/Linear/GitHub intake), LongHorizon-Harness (`AMAP-ML`, created Aug 4, 1,470 stars, manager/executor/auditor loop with intervention gates), diri (`cristicretu/diri`, created Aug 4, 285 stars), claude-code-merge-queue (`funador`, created Jul 10, 125 stars), OpenCrew (`opencrew-ai/opencrew`, created Aug 29, 11 stars, approval cards), Hyperlane IDE (commercial, v2026.09.0), Squad (ex-MissionControlHQ, $99/mo hosted, July 2026). Paperclip's Decisions desk + attention queue (Jul 20) and first stable channel (Aug 17) are the biggest feature changes among the incumbents.

**The one-line verdict up front:** nobody — first-party or third-party — implements criterion D as written (one hourly digest of every agent's pending questions with decision-ready context, immediate escalation only for urgent items). The closest surfaces are Paperclip's Decisions desk (a ranked pull queue with typed options, triage buckets and 7-day auto-lapse), Multica's merged Inbox, Operator's "awaiting input" inbox, AgentPulse's inbox with health classification, and first-party Agent View's "Needs input" group. All of these are *pull* surfaces that show questions immediately; none holds them for an hour and none distinguishes urgent from routine.

**Redundancy verdict:** first-party now covers E and F for local sessions, most of C for a single session, and gives strong primitives (hooks, `--json`, `defer`, messaging) for the rest. It does *not* cover A, enforced B across a fleet, or D.

## 2. Candidate tools

### 2.1 Paperclip — `paperclipai/paperclip`

**Description.** A self-hosted Node server + React UI that models a "company" of AI agents (org chart, CEO agent, roles, reporting lines) and drives them with *heartbeats*: an agent is dormant until woken by a timer, an assignment, an @-mention, or a Routine; each heartbeat runs budget checks, workspace resolution, secret injection, skill loading and adapter invocation, produces cost events and session state, then goes dormant. Work is Goal → Project → Issue → Execution workspace (git worktree by default) → Agent run, with Linear-like statuses, atomic issue checkout, blocker dependencies, budgets with hard stops, a runtime-enforced review → approval → done policy, per-issue **plan mode with plan approval**, a **Decisions** desk for agent-proposed choices, a **Blocked Inbox**, and **task watchdogs** that "treat every stopped leaf as a claim that has to be verified".

**Maker + maturity.** Pseudonymous maintainer (`cryppadotta`/"dotta"). **80,109 stars, 14,709 forks, 5,345 open issues**, TypeScript, **MIT**, created 2026-03-02, pushed **2026-09-06**. Install: curl installer, `npx paperclipai onboard`, Docker, or clone + pnpm (Node 24.11+); local, VPS/Fly.io, Kubernetes; no official hosted cloud (host-to-host Cloud Sync "retired upstream"). Release cadence since June: v2026.626 (Jun 26: task watchdogs, "ask" work mode), .707, **.720 (Jul 20: attention queue + Decisions surface, plan-approval continuations durable across failed wakes)**, **.817 (Aug 17: first stable channel; propose/decide Decisions with typed options and aging shelf; chat-style task view)**, .824 (managed runtimes over Tailscale; in-product Claude subscription sign-in via `claude setup-token`), .831 (skill library, Kimi adapter), .831.1 (Sep 2).

**How it drives Claude Code.** Local CLI subprocess via the `claude_local` adapter ("recommended"): probes with `claude --print - --output-format stream-json --verbose`; config `cwd`, `model`, `promptTemplate`, `maxTurnsPerRun` (300), `dangerouslySkipPermissions` (**default true**, "required for headless runs"); session IDs persisted and resumed with `--resume`; skills injected via `--add-dir`; auth via `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, or subscription login. Execution targets can be remote sandboxes (E2B, Modal, Daytona, Cloudflare, Kubernetes). Not the Agent SDK.

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| **2** — Goals are first-class; CEO agent drafts strategy for board approval; Routines (cron, default `0 10 * * *`) can assign the day's work | **2** — Per-issue plan mode: "The agent produces a plan document first. You review the plan before implementation begins"; versioned plans, Confirm/Decline, locked plan of record | **2** — Runtime-enforced executor → review → approval → done; agent changes-requested loops capped at 3 then escalate; watchdogs verify stopped work (e.g. require green CI link) | **1** — Decisions desk is a ranked *pull* queue (question + explanation + up to 8 typed options, triage today/this week/whenever, snooze, auto-lapse to "no" after 7 days) plus Blocked Inbox with urgency dots; **no hourly digest or push** — the official Slack/Discord how-to is a DIY routine that diffs against a last-seen cursor | **2** — Dedicated adapter, `--resume`, worktrees, sandboxes, in-product subscription sign-in | **2** — One dashboard: approvals card, Decisions, Blocked Inbox, activity feed, costs, timeline, chat-style task threads |

**Gaps.** No native Slack/email/Discord alerts (community plugin `mvanhorn/paperclip-plugin-slack`, 50 stars, has a 9 am daily digest); no Linear/Jira ticket sync (roadmap); `dangerouslySkipPermissions` on by default; no hosted option. **Risks.** Fast-moving (weekly releases, 5.3k open issues); heavy company/CEO metaphor if you only want a coding harness; pseudonymous single maintainer.

### 2.2 Symphony — `openai/symphony` (+ Claude Code ports)

**Description.** A spec (SPEC.md) plus an Elixir reference implementation: "for every open task, guarantee that an agent is running in its own workspace". It polls a tracker for issues in `active_states`, creates a per-issue workspace via `after_create` hooks, launches **Codex in app-server mode** as a subprocess, renders a `WORKFLOW.md` prompt (YAML front matter + Liquid body with `{{ issue }}`), and re-dispatches continuation turns until the issue leaves the active states. Ticket writes are done by the agent through injected tracker tools (`linear_graphql`, `github_api`, `jira_rest`, `asana_api`, `gitlab_api`).

**Maker + maturity.** OpenAI. **27,058 stars, 2,779 forks, 8 open issues**, Elixir, **Apache-2.0**, created 2026-02-26, pushed **2026-08-19** (last substantive commit Aug 12: token scrubbing). Tags v0.0.1 (Jul 18) and v0.0.2 (Jul 24). Note: the OpenAI launch post is dated Apr 27, 2026 but the repo's first commit is Mar 4 and third-party Claude ports were created Mar 5–13. June–August changes: opt-in dispatch labels (`tracker.required_labels`, Jun 4), generic tracker interface (Jul 18), GitHub Issues/Jira/Asana/GitLab adapters (Jul 20), Burrito single-binary releases, optional Phoenix LiveView dashboard with JSON API.

**Is the spec agent-agnostic?** Framed generically, but concretely Codex-only: "Coding-agent executable that supports the targeted Codex app-server mode"; the Codex app-server protocol "is the source of truth for protocol schemas, message payloads, transport framing, and method names"; sessions are Codex `thread_id`/`turn_id`. **Claude Code is not mentioned anywhere** in README, SPEC, or the launch post. Blocked/questions: by design, none toward the human — "This is an unattended orchestration session. Do not ask a human to perform follow-up actions"; "A run MUST NOT stall indefinitely waiting for user input"; blocked runs are shown only in the in-memory runtime state/dashboard. The human gate is the Linear `Human Review` state on a finished PR.

**Claude Code ports (all verified):** `joosure/Maestro` (46 stars, AGPL-3.0, Elixir, Linear + TAPD, last commit Jul 9 — "early-stage"); `cskwork/oh-my-symphony` (25 stars, Apache-2.0, Python, pluggable backends incl. `claude -p --output-format stream-json` with `--resume`, Linear/Jira/Markdown-kanban trackers, Textual TUI, **release 0.23.0 on Sep 6 — the only actively maintained one**); `gherghett/ClaudeCodePSymphony` (21 stars, no license, dead since Mar 9); `mscalessio/symphony-claude` (11 stars, dead since Mar 13); others ≤3 stars. Net: the Claude Code ecosystem around Symphony is thin.

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| **1** — Intake = tickets in `Todo` (optionally label-gated) in Linear/GitHub/Jira/Asana/GitLab; no goal concept | **1** — Prompt asks for up-front planning and a workpad; no plan-acceptance gate | **1** — One live agent per active ticket with retries/backoff and a dashboard; acceptance = human PR review via tracker state | **0** — Agents are forbidden from asking humans; blocked state is dashboard-only and in memory | **0** — Codex app-server only; Claude requires a fork | **1** — Tracker plus optional dashboard |

**Gaps/risks.** Codex lock-in; no human-facing notifications; blocked map lost on restart; quiet repo (8 open issues, no commits in 3+ weeks); Linear workflow needs custom states (`Rework`, `Human Review`, `Merging`).
**URLs.** https://github.com/openai/symphony · SPEC.md · `elixir/README.md`, `elixir/WORKFLOW.md` · https://openai.com/index/open-source-codex-orchestration-symphony/ (fetched via proxy; direct 403) · https://github.com/cskwork/oh-my-symphony · https://github.com/joosure/Maestro · https://github.com/mscalessio/symphony-claude.

### 2.3 Multica — `multica-ai/multica`

**Description.** "An open-source workspace where you assign work to AI coding agents the way you'd assign it to a teammate — they pick up the issue, report progress, raise blockers, and hand it back for review." A Linear-shaped control plane (issues, projects, board, inbox, chat, squads) where agents are assignees. A **daemon** on your machine (or a cloud runtime) claims runs and invokes any of 26 agent CLIs (Claude Code, Codex, Cursor, Copilot, Gemini, Kimi, Qwen, OpenClaw, …). Issues, comments and run records live on the server; code and CLI credentials stay on the runtime.

**Maker + maturity.** multica-ai (lead `forrestchang`). **49,053 stars, 6,337 forks, 1,511 open issues**, Go + Next.js + Postgres + Electron, created 2026-01-13, pushed **2026-09-05**, releases most weekdays (v0.4.31 Aug 20 → v0.4.40 Sep 4). **License: custom "Multica License"** (Apache-2.0 text plus: no hosted service to third parties, no embedding in a sold product, keep branding) — GitHub shows `NOASSERTION`. Install: Docker Compose script or Kubernetes; hosted multica.ai ("Start free trial", **pricing not published**, `/pricing` 404); desktop apps; `multica` CLI + daemon. Jun–Sep changes: plugin system + hook engine + Telegram (Aug 20), Public API v1, ZeroClaw ACP runtime, Inbox filters (Aug 24), prepaid seats, comment→sub-issue (Aug 25), Slack/Lark/DingTalk/WeCom/Telegram agent chat (Aug 26), Claude Fable 5.1 model gating (Sep 2), runs terminology + read replica (Sep 4).

**How it drives Claude Code.** Local CLI subprocess in stream-json mode (verified in `server/pkg/agent/claude.go`): `claude -p --output-format stream-json --input-format stream-json --permission-mode bypassPermissions` plus `--model`, `--max-turns`, `--resume <session>`, temp `--mcp-config`; stdin kept open; user overrides of `-p`/`--permission-mode` blocked. Daemon heartbeat 15 s; defaults 20 concurrent runs per daemon, 6 per agent. Workspace modes: Direct (in place, serialized per directory) or Parallel (git worktree per run; "Multica never merges it for you"; branch `agent/<agent>/<issue>`).

### 2.4 HumanLayer (formerly CodeLayer) — `humanlayer/humanlayer` + humanlayer.com

**Description.** "CodeLayer" as a name is gone. The open-source repo (Go daemon `hld`, Tauri WUI, `claudecode-go`, old SDK) now carries a 197-byte README: *"the code here is pretty much all deprecated — you can try the rebuild of humanlayer at https://humanlayer.com"*. The product is a **closed-source** rebuild: "a multiplayer coding agent IDE and cloud… the multiplayer control plane for your software factory". Its distinctive piece is the Research → Plan → Implement (RPI / QRSPI / PRD) workflow with **approved artifacts as gates**: "Implementation reads the latest approved artifact and changes the code one phase at a time. Checks run before the workflow moves on." Sessions run on a local or remote daemon; the UI (desktop/web/mobile) streams events via HumanLayer's API. Multiplayer: session sharing, task ownership transfer, collaborative diff review (Aug 2026).

**Maker + maturity.** HumanLayer Inc. (Dexter Horthy, Kyle Mistele; YC; ">$3M cumulative funding"). OSS repo **11,466 stars**, Apache-2.0 file (GitHub: Other), TypeScript, **pushed 2026-06-19**, last release `codelayer-0.1.0-nightly-20260227`; old SDKs removed (`@humanlayer/sdk` and PyPI `humanlayer` last published 2025-06-03). Product: 71 release notes Jun 6–Sep 5 (0.101.7 → 0.171.0): RPI default (Jun 6), kanban + team metrics (Jun 11), Free Hobby tier (Jun 17), one-way Slack notifications (Jun 26), GitHub issue import (Jul 20), unified Tasks workspace (Jul 31), diff review alpha (Aug 10), **session sharing / ownership transfer / multiplayer prompting (Aug 17)**, PR status in-app (Sep 5). Pricing: Starter free (3 members, 200 sessions/mo), **Pro $100/user/mo**, Enterprise; all BYOK. Install: `brew install humanlayer/humanlayer/humanlayer`; daemon `npm i -g @humanlayer/cli`.

**How it drives Claude Code.** Subprocess of the official `claude` CLI on a local or remote daemon ("the daemon launches Claude or Codex sessions"; "the daemon and the coding agents inherit the service's `PATH`"); also Codex, Copilot, Bedrock. Permission prompts surface per session in the UI; sharing a session lets others "prompt, interrupt, and resolve approvals". The old SDK's `require_approval`/`human_as_tool` Slack/email routing **no longer exists** (old docs 404). Slack is one-way and artifact-centric (PRD/TDD/outline/comment created); no approve-from-Slack, no email, no digest (only "a burst of comments syncing at once now plays a single notification sound").

## 4. Conclusions

### 4.1 Ranked shortlist (closest to the brief)

1. **Paperclip** (`paperclipai/paperclip`) — the only tool scoring 2 on A, B, C, E and F with a healthy, MIT-licensed, weekly-shipping project behind it: goals/projects/issues as first-class intake, per-issue **plan approval before implementation**, a runtime-enforced review → approval → done policy with **watchdogs that verify every stopped task**, a native Claude Code adapter with `--resume` and worktrees, and one dashboard. Its D is a ranked pull queue (Decisions desk with typed options, triage buckets, 7-day auto-lapse) rather than an hourly digest, and notifications are a DIY routine. Costs: heavy "AI company" metaphor, `dangerouslySkipPermissions` on by default, 5.3k open issues, no hosted option.
2. **Untrivial agent-orchestrator** (`Untrivial-ai/agent-orchestrator`) — the most mature open-source desktop control plane aimed squarely at this problem (11k stars, Apache-2.0, 94 contributors): worktree per task, hook-reported `blocked`/`waiting_input`, a kanban whose **Needs you / In review / Ready to merge** columns are derived from PR/CI/review facts, CI failures and review comments routed back to the owning session, reviewer agents, explicit merge. Weak on B (conversational planner, no per-task plan gate) and D (per-event notification center only; Slack/Discord dropped in the Go rewrite). Risk: 760 open issues post-rewrite.
3. **HumanLayer** (humanlayer.com, ex-CodeLayer) — strongest **plan gating** in the landscape (Research → Plan artifacts must be approved before implement; "checks run before the workflow moves on"), a task board by workflow stage, collaborative diff review, remote daemons running the `claude` CLI, and rapid iteration (71 releases this summer). Closed source at $100/user/mo, cloud-dependent, and its old Slack/email approval routing is gone.
4. **octomux** (`ShreyPaharia/octomux`) — the most *precise* fit for the human-attention layer: one inbox fed by Claude Code's native `PermissionRequest` hooks, a fail-closed `PreToolUse` gate on orchestrator dispatch, kanban, verify-loops, human-gated review publishing, and "Sweep" intake from a Jira filter or issue list. It is a 22-star, one-developer project — adopt only as a codebase to fork or as a design reference.
5. **Ivy-Tendril** (`Ivy-Interactive/Ivy-Tendril`) / **Fusion** (`Runfusion/Fusion`) — both score 10–11 because they have real plan-before-code gates and per-task verifications in one UI; Tendril is FSL-licensed .NET with thin docs, and Fusion's native path is its own harness (Claude Code is an opt-in provider through an ACP bridge), with a very large, weekly-changing surface. Worth a hands-on trial, not a bet.

Design references rather than adoptions: **codecast** (`cast decide` structured-decision contract + away-time email digest — the only tool that designed for D), **5dive** (tiered Tier-1/Tier-2 gates with regex floors for spend/secrets/destructive), **agent-deck**'s conductor (policy-filtered `NEED:` escalation on a heartbeat), **sortie** (ticket → verified PR with `needs-person` handoff), **LongHorizon-Harness** (manager/executor/auditor with intervention gates), and **claude-code-merge-queue** (check-gated landing) as a bolt-on acceptance step.

### 4.2 The least-served criterion

**D — interruption discipline — is unserved across the entire landscape.** Of ~60 tools examined, exactly one (codecast) has designed a batched, context-rich decision digest, and even it excludes permission prompts from the digest, cannot verify its cadence from the public code, and still pushes per event to the live inbox. Everything else falls into three buckets: (a) per-event push or badge (Agent View, Operator, omg.dev, AO, Superset, Multica, Paseo, t3code, Nimbalyst, Garcon, ccgram, OMC's Stop-hook callbacks, Gas Town mail); (b) "agents may not ask" (Symphony, sortie's `needs-person` termination, takopi, NEEDLE, kodo, Routines, Paperclip's default headless mode); or (c) a *pull* queue you must visit (Paperclip Decisions, Multica Inbox, cmux notification panel). Only Gas Town (severity → mail/email/SMS), 5dive (Tier-1 vs Tier-2 gates) and agent-deck (POLICY.md + `NEED:` filter) even model the *urgent vs routine* distinction, and none of them time-batches. Second least served is **B across a fleet**: enforced plan-acceptance-before-implementation exists in Paperclip, HumanLayer, Fusion, Tendril, Sculptor, Xum, Dex and ralphex, but first-party agent teams auto-approve teammate plans without review.

### 4.3 What can be extended cheaply to fill the gap

The cheapest route is not a third-party product but three first-party primitives that shipped this summer, glued by ~200 lines of script:

1. **Park questions instead of answering them.** Run each worker as `claude -p` (in a worktree, `--permission-mode` of your choice, or via the Agent SDK) with a `PreToolUse` hook matching `AskUserQuestion|ExitPlanMode` plus whatever permission classes you want humans to decide. The hook returns `{"hookSpecificOutput":{"permissionDecision":"defer"}}`; Claude Code exits with `stop_reason: "tool_deferred"` and a `deferred_tool_use {id,name,input}` payload, the pending call is preserved in the transcript, and **there is no timeout** (session files persist per `cleanupPeriodDays`, 30 days). Constraint: only when the turn has a single tool call; plan-mode resumes need `--permission-prompt-tool` (v2.1.246+). For in-process hosts, the Agent SDK `canUseTool` callback "can stay pending indefinitely" and `AskUserQuestion` arrives as structured `questions[]` with 2–4 options each — exactly the "full context needed to decide."
2. **Batch on a clock.** A supervisor (a `launchd`/cron job, a Desktop scheduled task, a `/loop 1h` in a background session, or a Routine with an API trigger) reads the queue of `deferred_tool_use` payloads (plus `claude agents --json` for interactive sessions in "Needs input", and `Notification` hooks of type `agent_needs_input`/`agent_completed`), writes one digest, and sends it through a Channels plugin (Telegram/Discord/iMessage, first-party) or Slack. Anthropic's own Routines example is literally "posts a summary to Slack"; `/loop` has a 1-minute floor and 7-day expiry; Routines have a 1-hour floor.
3. **Escalate only what matches an urgency floor.** Borrow 5dive's Tier-2 regex list (destructive commands, secrets, spend, publish) applied to the hook payload's `input` — those bypass the queue and push immediately (Remote Control's "Push when actions required", a Channel, or `notify_operator`-style webhook); everything else waits for the top of the hour. Answers are applied by `claude -p --resume <session-id>` (the hook returns `allow` with `updatedInput.answers` for `AskUserQuestion`, or `allow`/`deny` for permissions).

Among third-party tools, the cheapest extension points are: **octomux** (already converts native `PermissionRequest` hooks into an inbox table — add a scheduler and a Slack sender); **Paperclip** (Decisions desk + Blocked Inbox are queryable, the official how-to shows a scheduled notifier routine diffing a last-seen cursor, and the community Slack plugin already has a daily digest you could set to hourly); **cmux** (`cmux.json` notification hooks receive JSON on stdin — pipe into a digest for terminal-native setups); and **agent-deck**'s conductor (change `POLICY.md` and the heartbeat to emit one consolidated `NEED:` block per hour). Multica's Public API v1 and Operator's inbox are also reachable but less documented.

Two cost/policy facts to keep in view: (a) Anthropic's Agent SDK docs state "Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products" — tools that route your subscription OAuth through their own harness (Fusion's default path, Ruflo's subprocesses, Paperclip's subscription sign-in) sit in a grey zone, whereas spawning your own local `claude` is the intended path; (b) the planned separate "Agent SDK credit pool" for `claude -p`/SDK/GitHub Actions usage on Pro/Max ($20/$100/$200 per month) was **paused on June 15, 2026 ("For now, nothing has changed")** — several READMEs (e.g. ralphex) still describe it as live.
